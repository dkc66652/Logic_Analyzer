# 采集、查询与动态显示接口

本文记录已经移入 GUI 工程的六路逻辑分析仪采集链路，以及 Layer 1 的实际调用方式。

## 1. 已移植模块

- `Code/4_BSP/la`：TIM2/TIM5 六路双边沿输入捕获、DMA1 Stream0~5 和同步启停。
- `Code/2_Services/la`：采集任务、SDRAM 存储、MDMA 搬运和固定查询视图。
- `Code/4_BSP/fmc`：LA 存储层使用的 SDRAM/MDMA 兼容接口；SDRAM 芯片仍只由 GUI 设备层初始化一次。
- `Core/Src/dma.c`、`mdma.c`、`tim.c`：采集所需生成代码；`tim.c` 同时保留 GUI 的 TIM7 LVGL tick。
- `Core/Src/stm32h7xx_it.c`：DMA1 Stream0~5、TIM2 和 MDMA 中断入口。

采集数据数组由 `la_storage.c` 声明在 `.bss.LA_DATA`。链接后固定占用
`0xC0A00000~0xC1FFFFFF` 的 22 MiB SDRAM，不通过裸指针占用未声明内存，也不会由
`__main` 在 FMC 初始化前搬运或清零。

## 2. 启动和停止

显示侧通过以下适配接口控制采集：

```c
bool wave_capture_data_begin(uint32_t duration_cnt);
bool wave_capture_data_stop(void);
uint32_t wave_capture_data_get_now_cnt(void);
```

当前适配器请求 1 MHz 时间戳，所以 `duration_cnt` 的数值等于采集微秒数，1 CNT
等于 1 us。`wave_capture_data_begin()` 必要时先复位上一轮终态数据，再调用：

```c
LA_Service_Start(1000000U, duration_cnt);
```

LA Service 内部任务由 `LA_Service_Init()` 创建。开始按钮不直接操作采集任务，
也不直接启动 TIM/DMA。硬件侧每次始终同步采集全部六路；界面通道开关只决定
显示任务查询和绘制哪些通道。

## 3. 单通道窗口查询接口

Layer 1 每次只请求一个开启通道：

```c
bool wave_capture_data_request_channel(
    uint32_t channel_index,
    uint32_t s_tick,
    uint32_t e_tick,
    uint32_t window_tick,
    uint8_t columns[500],
    uint32_t *valid_columns,
    bool *initial_level);
```

- `s_tick`、`e_tick` 是当前可见数据范围，按左闭右开区间处理。
- `window_tick` 是完整 500 像素窗口对应的 CNT 宽度。
- `initial_level` 返回 `s_tick` 处第一条边沿之前的电平。
- `columns[x] == 0`：该像素列内没有翻转。
- `columns[x] == 1`：该列发生翻转，列末为低电平。
- `columns[x] == 2`：该列发生翻转，列末为高电平。

适配器使用一次 `LA_Service_Query_Try_Begin()` 固定当前查询快照，调用
`LA_Service_Query_View_Range()` 取得窗口左端电平和边沿范围，再按 128 个边沿 CNT
一批调用 `LA_Service_Query_View_Get_Data()`。边沿只顺序扫描一次，不会执行
`6 × 500` 次完整服务查询。所有退出路径最终调用 `LA_Service_Query_End()`。

`columns` 由波形任务提供。工程只保留一个 500 字节数组，在开启通道之间复用，
没有为六路各保留一份，也没有使用 500 项 16 位数组。

## 4. 动态显示与 DMA 顺序

每次 LTDC 帧通知到来后，波形准备任务锁存当前 CNT 和窗口，流程如下：

```text
如果通道布局刚改变：清空当前 Layer 1 后缓冲
for 物理通道 D1..D6
    如果界面未开启该通道：跳过查询和绘制
    查询该通道 [s_tick, e_tick) 的边沿
    转换为可复用的 500 字节列状态数组
    生成该通道高、低电平之间的 512 × 26 RGB565 横向条带
    把这一个通道条带送入 DMA 队列
等待最后一个开启通道的条带 DMA 完成
请求 LTDC 在垂直消隐期切换波形缓冲
```

DMA 队列严格保持通道顺序。正常动态显示时，开启几路就只查询并发送几块 26 行
条带；未开启通道不调用 LA 查询接口。两块 `512 × 26 × RGB565` 片内缓冲由准备
任务和 DMA 任务乒乓使用。LTDC 波形双缓冲在初始化时已清黑；通道布局改变后，
两个后续帧分别清理一次当前后缓冲，避免关闭通道留下旧像素。只有最后一个开启
通道的 `last_in_frame` 任务成功完成，DMA 任务才调用
`bsp_ltdc_lcd_wave_layer_present()`；查询或搬运失败时本帧不会切到前台，并在下一帧重试。

## 5. App CNT 示例

`Code/1_App/demo/app_wave_cnt_demo.c` 提供：

```c
App_Wave_Cnt_Demo_Query_Channel(...);
```

示例包含六路升序 CNT 边沿数组，展示调用方如何提供窗口、单通道数组和初始
电平，并使用同样的 `0/1/2` 列编码。它只用于接口说明，没有注册成 GUI 的真实
数据源；当前显示路径直接调用 LA Service 适配器。

## 6. 验证与剩余硬件工作

Keil Arm Compiler 6.24 完整构建为 0 错误、0 警告。map 文件已验证：

- `s_task_columns` 为 500 字节；
- 两个 DMA 条带共 53,248 字节；
- `la_storage_data` 位于 `0xC0A00000`，大小为 22 MiB。

当前 `GUI.ioc` 尚未写入 TIM1/TIM2/TIM5、DMA1 和 MDMA 配置，实际 Keil 工程使用
已经合并的生成源码。以后若用 CubeMX 重新生成，必须先把这些外设配置合并进
`.ioc`，否则会覆盖采集初始化。编译和 map 只能验证源码、符号和内存布局，六路
输入引脚、DMA 中断、实时查询与 LTDC/FMC 带宽仍需在目标板上联调。
