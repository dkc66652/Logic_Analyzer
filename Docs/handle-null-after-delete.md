# 删除内核对象后，句柄必须置空

> 适用：FreeRTOS 的队列 / 信号量 / 互斥量 / 任务句柄，以及所有"分配-释放"型的资源。

## 一、问题出在哪一行

看初始化函数的失败回滚路径：

```c
bool log_task_create(void)
{
    s_queue = xQueueCreate(LOG_QUEUE_LEN, sizeof(log_msg_queue_t));  /* 第一步 */
    if (s_queue == NULL)
    {
        return false;
    }

    if (xTaskCreate(...) != pdPASS)                                  /* 第二步 */
    {
        vQueueDelete(s_queue);       /* 第二步失败，把第一步的成果收回去 */
        s_queue = NULL;              /* ← 这一行不能省 */
        return false;
    }

    return true;
}
```

少了 `s_queue = NULL;`，`vQueueDelete()` 之后 `s_queue` 就变成**悬空指针**：
它仍然保存着原来那块内存的地址，但那块内存已经被内核还回堆里了。

## 二、三步连锁反应

**第一步：句柄变成野值。** `s_queue` 还是原来的地址，不是 `NULL`。

**第二步：判空保护失效。** `log_write` 里那句防守：

```c
if (s_queue == NULL)
{
    return false;                    /* 队列不可用，丢掉 */
}
```

本意是"队列没建好就别往里塞"。但悬空句柄是非 `NULL` 的，这个检查判定为"可用"，
于是继续往下走。

**第三步：往别人的内存里写。**

```c
xQueueSend(s_queue, &msg, 0);        /* 操作一块已经不属于你的内存 */
```

## 三、具体的破坏过程

假设堆的某一段地址是这样被复用的：

```
① s_queue = xQueueCreate(...)
   → 内核从堆里分配，返回地址 0x2400_1200
   → s_queue = 0x2400_1200

② vQueueDelete(s_queue)
   → 0x2400_1200 这块内存被还给 heap_4 的空闲链表
   → 但 s_queue 仍然是 0x2400_1200        ← 悬空

③ 之后 xTaskCreate(...) 分配任务栈
   → heap_4 把刚才那块地址又分出去了
   → 0x2400_1200 现在是一段任务栈

④ 别的任务调用 log_write() → xQueueSend(s_queue, ...)
   → 判空通过（因为不是 NULL）
   → 内核把"队列控制块"的数据写到 0x2400_1200
   → 实际写的是别人的任务栈
   → 任务栈被污染，任务跑飞 / HardFault
```

关键点：**地址被回收后会被重新分配给别人**。heap_4 还会把相邻的空闲块合并，
所以这块地址很容易在后续的 `xQueueCreate`、`xTaskCreate`、`pvPortMalloc` 里被拿走。

你写的是"发给日志"，实际改的是别人的数据。

## 四、为什么 `vQueueDelete` 不能帮你置空

因为它只拿到**句柄的值**——一个指针的副本。它改不了你那个变量。

C 是值传递。跟 `free()` 是同一个道理：

```c
free(p);
p = NULL;        /* 这一行必须你自己写，free 改不了 p */
```

这是 C 语言里所有"释放型" API 的共同限制：**API 负责释放，置空的活归调用者。**

## 五、为什么这类 bug 特别难查

1. **崩溃点和肇事者不在一个地方。** 报错可能在某个毫不相关的任务里，
   而真正的问题在几秒前一次日志调用。
2. **依赖内存布局。** 如果那块地址恰好没被别人拿走，程序一切正常；
   换个编译优化等级、加一个变量，内存布局一变就崩。
3. **依赖失败路径。** 只有 `xTaskCreate` 失败时才会删队列，而失败路径平时根本走不到，
   单步调试复现不出来。
4. **破坏是静默的。** 覆盖的是别人的栈或变量，不会立刻触发断言，
   可能几百次调用之后才崩。

## 六、正确写法

**原则：删除一个内核对象之后，立刻把句柄清成 `NULL`。**

```c
vQueueDelete(s_queue);
s_queue = NULL;          /* 让"删掉了"和"从没建过"在代码里表现一致 */
```

这样 `s_queue != NULL` 永远等价于"队列可用"，所有下游判断都只需要处理一种"不可用"状态。

## 七、同一个道理的其他地方

| 释放动作 | 必须配的置空 |
|---|---|
| `vPortFree(p)` / `free(p)` | `p = NULL` |
| `vQueueDelete(q)` | `q = NULL` |
| `vSemaphoreDelete(s)` | `s = NULL` |
| `vTaskDelete(t)` | `t = NULL` |
| `vEventGroupDelete(e)` | `e = NULL` |
| 关闭文件 / 释放句柄 | 句柄变量置 `NULL` |

## 八、自查清单

写任何"分配-释放"代码时，问自己三句：

1. **所有释放点，后面都跟着置空吗？** （包括失败回滚路径、错误分支、`vTaskDelete` 之前的清理）
2. **所有使用点，都做了空值检查吗？** （不能只有创建处检查）
3. **一个对象被删掉之后，代码里还有别的路径会用到它吗？**

第三问最要紧——**初始化失败的回滚路径**是最容易漏掉置空的地方，
因为它平时不执行，测不到。
