# GUI 工程项目结构

本文记录当前 **GUI 工程** 的实际代码归属。采集工程原有的结构说明完整保存在 [采集工程项目结构参考](采集工程项目结构参考.md)；两套工程的硬件、平台和链接差异见 [GUI 分层与采集工程合并差异](GUI分层与采集工程合并差异.md)。LA 采集、SDRAM 存储和查询算法已经移植；FatFs、压缩与协议服务仍只存在于参考工程。

## 依赖和接口

`main → App → Services → Devices / BSP → Platform` 是默认方向。入口按实际前置条件装配模块；业务层通过公开头文件调用下层能力。Layer 0 的右侧选项与左侧通道控件由 GUI 任务创建和访问；Layer 1 持有波形状态并提交 LTDC 波形后缓冲。它们之间通过 `layer1_wave.h` 和 `layer0_left_channels.h` 的接口交互。

- `layer0_left_channel_create()` 只接收文本、颜色和行位置，不读取采集状态；调用方在清空 LVGL 父容器后须丢弃返回的控件句柄。
- `side_panel_*()` 负责右侧导航与采集按钮，页面实现分别放在 `layer0_open_file.c`、`layer0_device_options.c`、`layer0_protocol_options.c`、`layer0_version_options.c`。
- `wave_*()` 保留原有六路界面配置和 Layer 1 绘制接口；`layer1_capture_data` 已直接适配真实 LA Service。硬件固定采集六路，波形任务只查询界面开启通道。
- 波形任务复用一个 500 字节单通道列数组，随后为该通道生成一块 `512 × 26` RGB565 横向条带。开启几路就按顺序发送几块，最后一块 DMA 完成后才提交 VBlank 换帧。
- `app_wave_cnt_demo.c` 给出六路升序 CNT 数组、窗口初始电平和相同列编码的独立示例，供同事确认 GUI 数据契约；它不注册为当前数据源。
- 设备和板级硬件操作不应放入 App。GUI 任务现在通过 `BSP_Lvgl_Tick_Start()` 启动 TIM7。
- LTDC 整屏缓冲和两块波形缓冲由 `bsp_ltdc_lcd.c` 的三个静态数组拥有，使用 `.bss.UI_DATA` 放入 SDRAM UI 区；显示代码通过数组地址访问。SDRAM 自检是设备层启动前的地址测试，不是显示缓冲的所有权接口。
- `resource_font.h` 在普通包含时只声明字库；仅 `app_init.c` 定义 `APP_FONT_IMPLEMENTATION`，以生成一份字形数据。

## 启动顺序

`Platform_Init → BSP_Init → Devices_Init → Platform_Runtime_Init → Services_Init → App_Init → vTaskStartScheduler`。BSP 先初始化 DMA1、MDMA、TIM7 和 LA 输入捕获；Devices 完成 SDRAM 芯片初始化和自检；Services 随后绑定 LA 的 SDRAM/MDMA 接口、创建 LA 任务和波形任务。`Platform_Runtime_Init` 在调度器启动前创建 1 s FreeRTOS 软件定时器，启动调度后由 Timer Service 维护 DWT 64 位时间。

## 构建与合并边界

Keil 工程已经加入 LA Service、TIM2/TIM5、DMA1 和 MDMA 源文件。链接脚本区域与采集工程一致，LA 数据使用 22 MiB `LA_DATA`，GUI 的 UART DMA 缓冲使用 `DMA_NOCACHE`。`GUI.ioc` 仍未同步采集外设，CubeMX 再生成前必须先合并 TIM1/TIM2/TIM5、DMA1、MDMA 和对应引脚/中断配置。MPU、日志串口、Fault、FatFs/SDMMC 等剩余差异见合并文档。
